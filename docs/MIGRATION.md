# 升级与迁移

ORVIBO Smart Control 使用独立的 `orvibo_smart_control` 集成域。
同域版本升级、内部配置格式迁移与从其他集成迁入，是三个不同过程。

## 同一集成升级

1. 备份 Home Assistant 配置、实体/设备注册及需要保留的媒体，记录当前集成版本。
2. 通过 HACS 更新，或整体替换 `<ha-config>/custom_components/orvibo_smart_control/`。
   手动安装应确认 `manifest.json` 位于该目录，避免嵌套或混入旧模块。
3. 重启 Home Assistant 加载 Python 模块；涉及卡片更新时强制刷新浏览器。
4. 检查账号、家庭和设备选择，先在一台设备上确认实体状态、实际动作及传输通道，再恢复自动化。

正常升级不需要删除配置项或重建实体。已有门锁媒体仍在
`config/media/orvibo_smart_control/`，通过集成独立媒体源读取，无需为 b14 之后的媒体源改动
搬动文件或新增 `media_dirs`。卡片资源自动更新，原有卡片类型和配置可继续使用。

## 升级至 2.0 版本线

`2.0.0b0` 基于 `0.2.6b17`，包含 `2.0` 分支的协议重构。
当前在 HACS 更新或重新下载 `v2.0.0b1`，重启 HA 并强制刷新浏览器即可加载。
GitHub 使用普通 Release / Latest，`bN` 不要求启用预发布。手动安装时应整体替换组件目录。
从开发分支安装时仍需记录 Git 提交和本地改动，以区分发布包与后续开发代码。

本次没有改变集成域、实体唯一 ID 前缀或配置项格式版本；协议相关变化如下：

| 设备 | 升级后应检查 |
| --- | --- |
| 原生类型 0/116 调光灯及其中虚拟 MixPad | HA 亮度与 App/物理亮度是否一致；最小、中间、最大值、零亮度及再次开灯 |
| 明确标记 RF 的 34/35 窗帘 | 只出现开、关、停，没有位置滑块；位置与关闭状态为未知 |
| 非 RF 窗帘、其他灯型及暖通 | 既有动作和状态仍符合设备表现 |
| Meari 摄像机 / NVR | 从 b1 起，选择页显示“支持实时视频”；其他 SDK 区分状态信息与视频支持，播放实体无需重建 |

自动化中直接读取灯光内部协议数值的逻辑应改用 HA 实体亮度；RF 窗帘自动化应使用开、关、停，
不能再依赖位置或 `is_closed` 判断到位。原生调光内部缓存统一为协议刻度，不需要手动转换或修改
HA `.storage`。完整公式与证据见 [2.0 协议重构](protocol-profiles-2.0.md)。

新增静态分支尚待真机验证。测试结果与历史媒体验证不能证明这些设备已兼容。

## 从其他 ORVIBO 集成迁入

1. 保留旧配置及备份，安装本集成，并通过 UI 重新选择区域、账号、家庭与设备。
   初始发现及重载仍需云登录，纯 LAN 模式也不例外。
2. 先选择少量设备，逐项确认 [设备支持矩阵](DEVICE_SUPPORT.md) 中的能力与通道。
   分阶段验证期间停用会重复驱动同一设备的自动化，避免两个集成同时发出动作。
3. 记录新旧实体对应关系，逐项更新自动化、场景、仪表盘与服务调用。
   本集成服务使用 `orvibo_smart_control`，卡片类型见 [服务与事件](SERVICES_AND_EVENTS.md)。
4. 验证完成后再停用旧集成；移除旧配置或数据前确认历史记录和媒体已妥善保存。

本集成不会自动导入其他集成的配置项、实体唯一 ID、历史记录、媒体归档或门锁姓名映射。
跨域重命名实体不等于迁移配置所有权，不能通过修改 `.storage` 域名替代正常配置。

## 内部配置格式迁移

当前 config flow 的内部 `VERSION` 为 `3`，与发布版本及分支名无关。
同域旧配置加载时由 `async_migrate_entry` 处理：将旧明文密码凭据转换为协议摘要并更新到版本 3。
摘要仍可用于认证，必须按密码保护。高于 3 的配置项版本会被拒绝迁移；缺少可迁移凭据时
迁移失败，应根据日志更新凭据或恢复有效备份。

`2.0` 版本线未增加配置项 schema 版本，也不要求重新填写姓名映射、设备选择或传输模式。
不要把内部版本 3、开发分支 2.0 和发布版本 `2.0.0b1` 混用。

## 回退与排查

遇到回归时，保留脱敏日志、设备型号/固件、传输模式、出错动作及开发代码记录。
同域开发代码可整体恢复为已知发布包并重启 HA；恢复后重新确认实体和自动化行为。
如果配置或实体注册也发生过人工变更，应使用升级前备份恢复，不能只靠覆盖 Python 文件撤销。

从其他集成迁入时，可暂停本集成并恢复仍保留的旧集成与自动化；本集成不会替用户清理旧实体。
设备发现、模式及媒体排查见 [项目 README](../README.md)，提交材料要求见
[安全策略](../SECURITY.md)。
