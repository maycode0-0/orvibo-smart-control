# v2.0.0b2

门锁总览卡片增加独立的开门记录；没有猫眼抓拍也能查看最近的开门，重载后仍保留。

- 开门记录按时间倒序展示，默认展开，可折叠或手动刷新；收到开门状态时自动刷新，不依赖摄像头实体。
- 内开只显示“内开”和时间，不保存或展示上次外开的人员、凭据方式或人员图标。
- 外开可显示锁侧上报的用户编号、当时映射的姓名和开锁方式；修改姓名映射不会改写已保存的历史。
- 新增 `list_openings` 服务；开锁和 30 秒归属窗口内的门磁开门合并为一条记录。
- 每把锁最多保存 500 条，沿用 7 天定期清理策略，也可通过 `cleanup_history` 手动清理。

记录从升级后收到的事件开始积累，不从历史抓拍推断或回填。内外开仍按既有凭据规则推断，
不代表锁侧明确上报方向。原有实体、姓名映射和卡片配置可保留。

在 HACS 更新或重新下载 **v2.0.0b2** 后，**重启 Home Assistant，并强制刷新浏览器**。
手动安装可下载 Release 中的 `orvibo-smart-control.zip`，解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换旧组件后重启。

验证：Python 3.12 全量运行 **835 项，833 项通过、2 项因本机缺少 FFmpeg 跳过**，覆盖记录持久化、
事件合并、并发保存、卸载、设备隔离、响应校验及内开身份隐藏。发布 CI 安装 FFmpeg 后执行
全量测试、HACS validation 和 hassfest。

已有模拟浏览器检查覆盖深浅色窄列布局、折叠、自动刷新、失败保留及手动恢复；本次开门记录
尚未在真实 Home Assistant 与门锁上验证。2.0 新增的 116、虚拟 MixPad 调光和 RF 34/35 分支
仍为 `hardware_verified=false`。

本版按普通 GitHub Release / Latest 发布，`Pre-release=false`；下一次临时版本为 `2.0.0b3`。
