# 2.0.0b9 MixPad 音乐控制修复

修复 b8 中音乐实体已经出现、HA 点击播放无报错但设备不播放的协议错误。
用户反馈环境为 MixPad 7 Ultra / QQ 音乐，官方 App 可以正常播放。

APK 音乐请求构造器实际使用 `cmd=289`，b8 误用了普通设备控制的 `cmd=15`。
本版将播放、暂停、切歌、音量、静音、跳转和初始状态查询统一改为 `289`，
补上 `289` 音乐状态响应分发，并移除不属于该云端正文的 `delayTime`。
普通灯具、窗帘等原有 `cmd=15` 控制保持独立。

音乐控制发送失败时，媒体实体会向 HA 返回错误；云端明确拒绝的音乐响应会记录状态码，
其中的状态条目不会更新设备。成功写入连接仍不代表设备已经执行，需结合实际声音和回报状态验证。

在内置市场或 HACS 更新到 **v2.0.0b9** 后，**重启 Home Assistant**。
音乐实体沿用原有唯一 ID，无需删除集成或重新配对。
手动安装可将本 Release 的 `orvibo-smart-control.zip` 解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换后重启。

验证重点：先在智家365 App 播放 QQ 音乐并暂停，然后在 HA 验证播放/暂停、切歌、
音量和 App/HA 状态同步。仍需默认结合模式或纯云端模式；不提供任意 URL 播放或音源选择。

离线回归覆盖实际 AES 音乐封包、加密 `289` 响应接收、普通 `15` 与音乐分离、
拒绝响应过滤、媒体动作失败反馈及既有协议，Python 3.12 定向运行 **147 项全部通过**。
Python 编译、翻译 JSON 和 `git diff --check` 通过。完整测试、HACS validation 与 hassfest
通过后，发布流程才生成公开安装包。

协议修复依据为智家 365 `5.2.6.307` APK 的 REA/JADX 静态证据，详见
[协议档案](../protocol-profiles-2.0.md#mixpad-背景音乐b8-引入b9-修正命令号)。
尚未执行修复后的真机控制验证，`hardware_verified` 保持 false。

本版为普通 GitHub Release / Latest，`Pre-release=false`；下一次临时版本为 `2.0.0b10`。
