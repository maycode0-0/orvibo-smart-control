# 2.0.0b7 实时视频持续丢包恢复

此临时诊断版补上实时视频接收中的 KCP 丢包恢复，针对后续完整关键帧已到达、
却一直被缺失片段阻塞到取流超时的情况。继承 b6 的共享读取、通道补发现和卡片恢复。

在 HACS 更新或重新下载 **v2.0.0b7** 后，**重启 Home Assistant 并强制刷新浏览器**。
手动安装可下载 Release 中的 `orvibo-smart-control.zip`，解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换旧组件后重启。

- 同一个 KCP 缺口先等待 2 秒，给短暂乱序和重传保留机会；持续缺包时才丢弃损坏
  消息的残片，从后续完整消息边界继续，等待实际 H.264/HEVC 关键帧及参数集后输出。
- 即使发送方窗口已满、没有新 UDP 包，也会消费恢复后的消息队列，并重发推进后的
  累计 ACK，避免接收端和发送方相互等待。仍保留内存上限和原有取流时限。
- 录像查询和录像回放不使用有损跳片；厂商 I 帧标签本身不足以解除关键帧门控。

验证：Python 3.12 全量 **890 项测试通过，无跳过**，包含真实 FFmpeg 转码和 PyAV
双读者连续解码。新增回归先在旧代码上复现首帧前无帧超时、播放后后续帧阻塞，再
验证修复后在无新包时恢复；覆盖 H.264/HEVC、残片丢弃、实际关键帧门控、累计 ACK、
短暂乱序保留全部帧，以及录像查询和回放隔离。

真机观察来自更新前的 `2.0.0b6`：露台 NVR 通道 3 云端在线，但反复出现无帧、超时
和本地 HTTP 503，期间曾暂时恢复播放。离线回归确认了实现缺口，尚未证明真机每次
中断均由此触发；本版修复尚待升级后的露台通道连续播放验证。硬盘与 SD/TF 回放仍
待真实设备验证，不提升任何 `hardware_verified` 标记。

按普通 GitHub Release / Latest 发布，`Pre-release=false`；下一次临时版本为 `2.0.0b8`。
