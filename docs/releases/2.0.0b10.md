# 2.0.0b10 MixPad 动态文字播报

增加 `orvibo_smart_control.speak`，让 HA 自动化将每次传入的文字交给 MixPad 播报。
需要先在智家365 App 创建名称唯一的专用场景，例如“HA语音播报”，其中仅包含目标
MixPad 的一条“语音播报”动作，并在 App 手动执行确认能够发声。

在内置市场或 HACS 更新到 **v2.0.0b10** 后，**重启 Home Assistant**，执行：

```yaml
action: orvibo_smart_control.speak
data:
  scene_name: HA语音播报
  message: 欢迎回家
```

多个集成配置项时还需填写 `entry_id`。场景名称精确匹配；文字最多 300 字，
支持中文、英文字母、数字、空白及 `，。！？,.!?`，与 App 普通播报编辑器一致。
需要默认结合模式或纯云端模式。

每次调用先更新专用场景文字，收到匹配的云端成功响应后再触发场景；App 会保留最后一次文字。
场景含其他活动动作、名称重复或数据不完整时拒绝执行。并发调用串行处理；更新或执行
未获确认时向 HA 报错，不自动重试。执行超时后请先检查面板，避免重复播报。
返回成功表示云端确认触发，仍需听到实际声音确认效果；不恢复先前文字或音乐状态。

用户已经确认 b9 在 MixPad 7 Ultra / QQ 音乐上能正常播放，也确认官方 App 场景能播报。
本版 HA 动态文字路径尚待实机测试，`hardware_verified` 保持 false。
任意音频 URL 和文件播放仍未建立可用格式，不提供 `PLAY_MEDIA` 或 `tts.speak` 目标能力。

Python 3.12 定向回归 **104 项通过**，覆盖场景校验、文字边界、加密封包与响应分发、
超时不重放、并发顺序、多配置项选择、服务错误与既有音乐/SSL 控制。
本机全量检查出现原有视频测试的 FFmpeg 版本不兼容及进程时序失败；相关视频实现未修改。
发布工作流必须通过 Linux 全量测试、HACS validation 和 hassfest 后才生成公开安装包。

安装与协议依据见 [文字播报指南](../mixpad-audio-playback.md)。本版为普通 GitHub
Release / Latest，`Pre-release=false`；下一次临时版本为 `2.0.0b11`。
