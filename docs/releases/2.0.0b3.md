# 2.0.0b3 摄像机首次连接与断线重试修复

此临时诊断版针对实时画面频繁显示 `Media unavailable`、HA Stream 记录本地视频桥
5XX / I/O error 的情况，修复两类已由离线回归复现的连接恢复问题：

- 首次打开与后续重试共用有时限的 P2P/转码准备。HA 读取先超时或取消后，下一次
  请求可以继续使用该准备，避免反复从头连接；无人使用的结果仍会过期回收。
- 首次预连接失败也会触发有次数与总时限限制的后台恢复。
- HA 断开后立即重试时，短暂等待旧连接清理完毕，减少旧请求占用视频桥导致的 503。
- 增加 `http_503_count`、`last_http_error_reason`，区分读取占用、源建立失败和桥关闭等原因。

在 HACS 更新或重新下载 **v2.0.0b3** 后，**重启 Home Assistant**，再打开实时画面。
手动安装可下载 Release 中的 `orvibo-smart-control.zip`，解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换旧组件后重启。

验证：Python 3.12 全量 **840 项测试通过，无跳过**，包含真实 FFmpeg HEVC→H.264
MPEG-TS 转码与 PyAV 连续解码，以及慢速首次连接取消、失败恢复、重试次数上限、
无人使用连接回收和断线立即重试。对应旧逻辑已先验证无法通过新增失败场景。
发布 CI 执行全量测试、HACS validation 和 hassfest。

这些离线结果不能确认用户真机上全部 5XX / I/O error 的触发原因；首次打开和连续
播放稳定性仍需实际 HA 验证。`streaming` 表示视频桥输出过数据，不代表浏览器已成功播放。
若仍出现问题，请保留实体 `video_diagnostics` 与 HA Stream 日志。
2.0 新增的 116、虚拟 MixPad 调光和 RF 34/35 分支仍为 `hardware_verified=false`。

本版按普通 GitHub Release / Latest 发布，`Pre-release=false`；下一次临时版本为 `2.0.0b4`。
