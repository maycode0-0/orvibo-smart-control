# 2.0.0b5 摄像机可选流畅画质

此临时诊断版增加“摄像机实时画质”设置。流畅档根据当前摄像机或 NVR 当前通道
上报的能力请求标清码流，从源头减少需要处理的视频数据；画面细节可能降低。
没有已知标清档的设备保留默认码流。升级后仍使用默认档，需手动选择流畅档。

在 HACS 更新或重新下载 **v2.0.0b5** 后，**重启 Home Assistant**，进入
“设置 → 设备与服务 → ORVIBO Smart Control → 配置 → 摄像机实时画质”，选择
“流畅”并保存。保存会重新加载集成，再打开单路实时画面对比稳定播放时的 CPU 曲线。
此设置对该配置项全部实时预览生效；录像回放继续使用原有独立请求。

实时实体的 `video_diagnostics` 新增：

- `requested_quality`：`default` 或 `fluent`。
- `requested_stream_id`：首个可输出关键帧到达后显示发送的请求编号；`0` 表示默认请求，
  `100` 为现代标清档，`1`、`2`、`3` 分别为旧能力表中的 360P、240P、480P 档。

这些字段描述请求，不能证明固件已按该档返回画面；实际编码仍以 `source_codec` 为准。
流畅档不保证改为 H.264，当前软件转码仍会运行。用户在 b4、2 vCPU / 4 GiB 虚拟机中
报告的单路总 CPU 约 38%–43%；本版的实际分辨率、CPU 降幅和首次加载稳定性仍需真机验证。

验证：Python 3.12 全量 **856 项测试通过，无跳过**，包含真实 FFmpeg 转码与 PyAV 解码。
新增配置保存/校验、仅实时实体应用、标清能力门控、VVP 请求字节一致性、私有参数传递
和公共诊断过滤回归。画质映射依据 HomeMate 5.2.6.307 的现有 JADX/Apktool 导出，
本轮未执行 APK、未联网操作真实摄像机，不提升任何 `hardware_verified` 标记。

手动安装可下载 Release 中的 `orvibo-smart-control.zip`，解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换旧组件后重启。
本版继承 b4 的解析 CPU 优化和 b3 的首次连接恢复、断线重试与 503 诊断。

按普通 GitHub Release / Latest 发布，`Pre-release=false`；下一次临时版本为 `2.0.0b6`。
