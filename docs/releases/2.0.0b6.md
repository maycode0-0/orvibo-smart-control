# 2.0.0b6 实时视频共享读取与通道、卡片恢复

此临时诊断版修复摄像机同时被 HA Stream 和 go2rtc 读取时的冲突，并补上在线通道
恢复后的自动发现与仪表盘卡片启动恢复。继承 b5 的可选流畅画质。

在 HACS 更新或重新下载 **v2.0.0b6** 后，**重启 Home Assistant 并强制刷新浏览器**。
手动安装可下载 Release 中的 `orvibo-smart-control.zip`，解压到
`<ha-config>/custom_components/orvibo_smart_control/`，整体替换旧组件后重启。

- 同一实时实体最多 4 个本地源读者共用一套协议接收与 FFmpeg，避免第二个正常读者
  固定遇到 `source_busy / 503`。慢读者单独退出，关闭一个读者不会中断其他读者；
  最后一个读者退出后回收共享进程。录像回放仍需独立选择且独占读取。
- 每 60 秒查询选中设备的云端通道清单，补注册首次加载缺失、之后恢复的实时和回放
  实体。查询只获取元数据，不自动开流；云端临时失败或空清单不删除已有实体。
- 门锁、临时密码和录像回放卡片注册后最多检查 30 秒，覆盖仪表盘或缺失组件错误
  稍晚出现的情况。仅恢复明确提示已注册 ORVIBO 组件缺失的错误；同一错误节点只
  处理一次，每页最多重建 3 次。正常页面、其他组件和实际配置错误不触发重建。

实时诊断新增 `active_readers` 和 `slow_reader_count`；`reader_limit` 表示本地源读者
达到上限。`source_busy` 仍用于独占录像回放。这些字段不证明实际播放一定稳定。

验证：Python 3.12 全量 **887 项测试通过，无跳过**，包含真实 FFmpeg 转码与 PyAV
已有读者、晚加入读者连续解码；覆盖慢读者隔离、取消与卸载、共同源故障恢复、回放
隔离、通道恢复去重和 16 项卡片启动场景。此前全量测试曾有两项在首帧后 0.1 秒注入
源故障的用例首次响应为 503，单独复核和再次全量均通过，保留该时序波动记录。

真机证据来自升级前的 b5：4 vCPU 环境下，NVR 通道 1 流畅档实际返回 H.264 /
640×360 / 码流 100，原生 WebRTC 播放器时间推进超过 5 分钟；露台通道 3 云端在线
但 HA 仅保留历史实体，重载后恢复出画。期间仍有源错误与 `source_busy / 503`，
没有采集 CPU 曲线。40 次页面刷新未捕获原始偶发卡片故障。

本版共享读取、自动发现和卡片恢复尚待升级后的真机验证，不能认定全部加载问题已
解决。硬盘与 SD/TF 回放仍待真实设备验证，不提升任何 `hardware_verified` 标记。

按普通 GitHub Release / Latest 发布，`Pre-release=false`；下一次临时版本为 `2.0.0b7`。
